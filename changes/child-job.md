- A host that is killed with no cleanup (SIGKILL, a crash, `TerminateProcess`) no longer leaves its stdio servers, nor the server behind `cmd /c` or `sh -c`, when that server ignores the end of its input. Outside Windows a `/bin/sh` watchdog for each host, and for the broker, lists the process group of each child and ends the groups that are left when its input ends. It adds about 1 MB, and `TOOLSCRIPT_CHILD_GUARD=0` turns it off. On Windows it is off: `TOOLSCRIPT_CHILD_GUARD=1` compiles `runtime/child-guard.cs` one time with the `csc.exe` of .NET Framework 4 into `~/.toolscript-mcp/guard` and starts it for each host and broker (about 16 MB private, ready in 70 to 100 ms warm). The program puts each child in a Job Object that Windows closes with the host. A program that Defender stops (rule `01443614-CD74-433A-B99E-2ECDC07BFC25` in block mode) leaves the guard off with one stderr line, and every server still starts. Only pids reach the guard. `toolscript-mcp doctor` has a `child-guard` line. See "Child guard" in the README.
