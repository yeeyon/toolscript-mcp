- `init` imports the user-scope servers of Codex (issue #86). It reads them from `codex mcp list --json` and `codex mcp get <name> --json`, or from `config.toml` when `codex` is not on `PATH` or a call fails. It maps `env_vars`, `bearer_token_env_var`, `http_headers` and `env_http_headers` to `${VAR}` references, and turns `enabled_tools` and `disabled_tools` into policy rules that are never looser than Codex. It prints the Codex steps: the TOML entry of toolscript with `default_tools_approval_mode = "approve"`, and `codex mcp remove <name>` for each server. It leaves out `http_headers_helper`, the timeouts and each key that it does not know, with a printed reason, and never prints a literal value of `env` or a header.
- `init` no longer reports a conflict for the same server in two clients when only the order of the keys of its entry differs, such as `env` or the fields of `command`. The two entries are the same, and the first client wins as before. This holds for every client, not only Codex. An `args` list in another order is still a conflict.
